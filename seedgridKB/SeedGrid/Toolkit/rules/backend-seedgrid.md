# Padrões comuns do back-end SeedGrid

Regras **obrigatórias** para quem usa o SeedGrid num back-end, seja qual for a linguagem. Cada regra tem um id (`BE-nn`) para citar em revisões (`sg-review`). Esta rule diz **o quê**; a rule da linguagem diz **como**: em Java, `backend-java-seedgrid.md`. Os ids são os mesmos nas duas: esta traz a regra, e a da linguagem acrescenta o que só vale nela.

Para as extensions (propriedades, enums, exemplos), consulte a KB: comece por `.ai/brain/SeedGrid/Extensions/Indice.md`. A coluna "Rust" do índice indica o crate equivalente.

## Dados

- **BE-22.** Chave primária no PostgreSQL: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
- **BE-24.** Índice único para o `publicId`: `CREATE UNIQUE INDEX idx_<table>_public_id ON <table>(public_id);`.
- **BE-25.** Proibido `UPDATE` em massa por JPQL ou SQL direto: quebra a auditoria e ignora regras de negócio.

## API

- **BE-30.** **Nunca** exponha `id`; exponha sempre `publicId`.
- **BE-32.** Filtros de busca textual usam `LIKE` por prefixo (`term + "%"`), nunca `"%" + term + "%"`.

## Erros

- **BE-11.** Exceptions/erros **tipados** que reflitam o objetivo; nunca lance um erro genérico (`RuntimeException` em Java; em Rust, tipos de erro próprios e sem `unwrap`/`expect` em caminho de requisição). Detalhes por linguagem na rule da linguagem.

## Testes

- **BE-40.** Todo projeto tem testes unitários e testes de integração com Testcontainers + PostgreSQL. Código sem teste não é considerado pronto.
- **BE-42.** **Testes-guardiões** protegem uma invariante crítica de negócio ou segurança cuja violação causa dano irrecuperável (exemplo: toda empresa/tenant mantém ao menos um usuário ativo com a role ADMIN; sem isso o cliente perde o acesso administrativo para sempre). Convenção:
  - Nome da classe termina em `GuardianIT` (integração, Testcontainers + PostgreSQL) ou `GuardianTest` (unitário), por exemplo `LastAdminGuardianIT`. O sufixo `Guardian` sozinho **não roda**: o surefire/failsafe (Maven) só executa classes que casam o padrão `*Test`/`*IT`. Em outras linguagens, use o nome que o runner do projeto executa e mantenha o `Guardian` no nome.
  - Comentário/Javadoc no topo da classe com: o que a invariante protege, por que existe, o dano se for quebrada e quais caminhos cobre, mais o aviso: "TESTE-GUARDIÃO: NÃO ALTERAR, ENFRAQUECER, DESABILITAR (@Disabled), REMOVER ASSERTS nem relaxar expectativas sem decisão EXPLÍCITA do dono do projeto."
  - Cobre **todos** os caminhos que podem violar a invariante (endpoints, services, fluxos de host, desativação por conta etc.), não só o caminho feliz.
  - Se um guardião falhar, o defeito está no código de produção, não no teste. Nunca ajuste o teste para passar; se parecer que o teste está errado, pare e pergunte ao dono. Alterar um guardião só com autorização explícita do dono, registrada na mensagem do commit.

## Extensions/crates SeedGrid, LGPD e auditoria

- **BE-60.** Use as extensions (Java) ou os crates (Rust) SeedGrid antes de escrever código próprio de autenticação/permissões (`security`), auditoria (`audit`), notificação, billing, cache, storage, rate limit etc. Consulte `.ai/brain/SeedGrid/Extensions/Indice.md` e configure pelas propriedades documentadas. Código próprio só quando nenhum cobre, com a justificativa na entrega.
- **BE-61.** Dado pessoal (CPF, CNPJ, inscrição estadual, e-mail, telefone, WhatsApp, logradouro; nome quando identifica a pessoa e data de nascimento também) usa o `privacy` do SeedGrid, **pelo que o campo representa**: cifrado em repouso e com hash de busca em todo campo cifrado. Anotações e colunas na rule da linguagem.
- **BE-62.** A cifra de campo é opt-in: o projeto liga a cifra e fornece as chaves por segredo/variável de ambiente, nunca em arquivo versionado.
- **BE-63.** Dado pessoal **não** vai em claro para auditoria, log, exportação ou resposta de erro: use o mascaramento do `privacy` (e remoção total para senha e segredos).
- **BE-64.** Todo método de service é auditado pela extension/crate `audit`, inclusive a leitura (para saber quem leu).
- **BE-65.** Endpoints protegidos pelo mecanismo de segurança da extension `security`; a UI esconder um botão não substitui a checagem no back.

## Ao terminar

- **BE-50.** Revise se não sobrou nada (classes e arquivos que deveriam ser removidos) e liste os TODO que ficaram no projeto.
